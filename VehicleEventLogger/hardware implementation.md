# HARDWARE_IMPLEMENTATION.md

## Hardware Implementation

The Vehicle Black Box Event Logger was successfully implemented on a **Xilinx Artix-7 FPGA**. After completing functional verification through simulation, the design was synthesized, implemented, and programmed onto the FPGA using the Xilinx Vivado Design Suite. The hardware implementation validates the complete operation of the system, including event detection, memory storage, log retrieval, and UART communication.

The FPGA board interfaces with slide switches, LEDs, a keypad, and a UART output. The slide switches are used to simulate various vehicle events, while the keypad is used to initiate the transmission of stored event logs. LEDs provide immediate visual feedback regarding the system status, including event detection, write operations, and timestamp activity. The UART output is connected to a host computer, allowing the logged events to be displayed on a serial terminal such as PuTTY.

The implemented design demonstrates reliable real-time operation by detecting events, storing them with timestamps, and transmitting the stored records in a structured format upon user request.

## Hardware Operation

### 1. System Initialization

After programming the FPGA, the system is initialized by asserting the reset switch. This clears the timestamp counter, memory pointers, entry counter, and all stored data, preparing the logger for a new recording session.

---

### 2. Event Detection

Vehicle events are simulated using the FPGA slide switches. When a switch corresponding to a specific event is activated, the Event Encoder detects the event, generates the appropriate Event ID, and asserts the `event_valid` signal.

---

### 3. Event Logging

Upon receiving the `event_valid` signal, the Logger FSM generates a single write enable pulse. The current timestamp and Event ID are latched and stored in the Log Memory at the address generated by the Write Pointer. The Entry Counter simultaneously updates the number of valid log entries stored in memory.

---

### 4. Log Retrieval

Pressing any key on the keypad generates a debounced pulse that triggers the UART Controller. The Read Pointer sequentially accesses each stored memory location, and the Read Controller extracts the timestamp and Event ID from every log entry.

---

### 5. UART Transmission

The retrieved timestamp is converted into ASCII digits, while the Event ID is translated into a readable event name. The UART Controller formats the complete log with headers and separators before sending the data to the UART Transmitter. The UART Transmitter serially transmits the formatted log to the host computer, where it is displayed on PuTTY.

## Hardware Validation

The implemented design was validated on the FPGA by performing the following tests:

* Resetting the system using the reset switch.
* Generating each vehicle event using the assigned slide switches.
* Verifying correct Event ID generation through LED outputs.
* Confirming successful write operations using the Write Enable indicator.
* Observing continuous timestamp generation.
* Retrieving stored log entries through the keypad.
* Displaying the transmitted logs on PuTTY through the UART interface.

The hardware implementation confirmed that all functional modules operated correctly and communicated seamlessly as an integrated system. Event detection, timestamp generation, memory storage, sequential log retrieval, ASCII conversion, and UART transmission were successfully verified on the Artix-7 FPGA.
